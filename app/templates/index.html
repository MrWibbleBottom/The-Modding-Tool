          Help & Feature Guide — How Everything Works
          Reference
        

        

          A complete breakdown of every tab, button, and background process in the application.
        

      


      

        
1. Game Manager & Library

        

          

            
Game scan, Filter & Prune Non-Games

            

              Discovers installed PC games across Steam, Epic Games, GOG Galaxy, Xbox / PC Game Pass, Ubisoft Connect, EA Games, or a custom folder path (up to 3 subdirectory levels). Excludes engines/redistributables/servers/editors (UnrealEditor.exe, Steamworks, Proton, Dedicated Servers), tracks live progress on the inline progress bar, exposes output in the closeable Game Scan Log, and offers Prune Non-Games + Game Library (owned/CSV/JSON imports).
            

          

          

            
Game info, Pinning & Quick Load

            

              Game info inspects each game folder to populate engine, scripting backend, anti-cheat status, and recommended MCP stack. Click Load Game, pick from the top Quick Load dropdown, press Ctrl+K (Command Palette), or Pin favorites to switch active workspace profiles immediately.
            

          

          

            
Browse, Add/Edit Game & Icons

            

              Lets you pick any local folder, manually configure a game profile, or extract and cache `.exe` icons via Pre-warm Icons.
            

          

        

      


      

        
2. Active Game, Readiness & Safety Nets

        

          

            
4-Step Modding Readiness Strip & Fingerprint

            

              Tracks 1. Fingerprinted, 2. Clean Snapshot, 3. Modding Stack Ready (with Vortex/MO2 or proxy-DLL conflict badges), and 4. Workspace / Bridge Ready, with inline Fix / Run actions on incomplete steps. Fingerprint & Rescan inspects key binaries and refreshes metadata.
            

          

          

            
Snapshots, Conflict Guard, Provision & Restore

            

              Snapshots & Rollback captures modded surfaces (BepInEx/plugins, BepInEx/config, doorstop_config.ini, ~mods, Unreal .inis) for one-click rollback and auto-snapshots before loader, mod, or INI edits. Conflict Guard flags existing Vortex/MO2 setups or proxy DLLs (winhttp.dll, dwmapi.dll) before overwriting. Provision & Clean Restore verifies BepInEx archives by SHA-256 and deploys cleanly.
            

          

          

            
Steam Artwork, Unreal Advisor, Asset Audit & Live MCP

            

              Displays local Steam librarycache artwork, scores Unreal Engine INI settings against your PC Specs (Green / Amber / Red) with Apply/Restore INI controls, audits open vs. restricted mod layers in the Asset & Moddability Analyzer, and connects over persistent stdio to bepinex-mcp for live Unity inspection/editing.
            

          

        

      


      

        
3. Build a Mod

        

          

            
How Mod Building Works

            

              Import live MCP edits, add Harmony hook rules, or define custom edits, then click Build Compatible Mod:
              
• Unity IL2CPP / Mono: Generates a BepInEx C# plugin with Config.Bind entries and scene-load hooks, compiles it directly against game/interop/Managed assemblies via dotnet build, and packages a distributable .zip with INSTALL_INSTRUCTIONS.txt.
              
• Unreal Engine 4/5: Generates an RE-UE4SS main.lua script + GameUserSettings_Override.ini + INSTALL_INSTRUCTIONS.txt package.
              
• Install Built Mod to Game runs Conflict Guard + an automatic safety snapshot before copying files into the game directory.
            

          

        

      


      

        
4. PC Specs & Audit Log

        

          

            
PC Specs

            

              Scrapes CPU, GPU (VRAM, driver), RAM, drives, OS, and display resolution/refresh rate, caches results in pc_specs.json, and maps your hardware to the Unreal Engine Reference Array.
            

          

          

            
Audit Log

            

              Records every game or app action and sanitized failure (ACTION_FAILED, GIT_PUSH_FAILED) with UTC timestamps, categories (Game / App / All), and SHA-256 integrity hashes in %LOCALAPPDATA%\TheModdingTool\audit.jsonl.
            

          

        

      


      

        
5. App Management

        

          

            
GitHub Distribution, Branches & Push Safety

            

              Configure owner/repo/token, check remote updates, pull available branches into the Push Branch selector, review uncommitted files, and push safely with a branch confirmation warning modal or roll back to pre-sync snapshots.
            

          

          

            
Portable Export, Offline Control & Protocol

            

              Packages a standalone TheModdingTool.zip, registers the moddingtool://start Windows protocol handler, and exposes Stop Server / Restart App with an offline service-worker fallback page (/offline).
            

          

          

            
Tool Upgrades, Diagnostics & UI Customization

            

              Upgrades BepInEx 6, BepInExMCP.IL2CPP, RE-UE4SS, and MelonLoader with HTTPS & SHA-256 verification; inspects Python/.NET diagnostics; and customizes app title, accent color, custom banner/favicon uploads, tab visibility, and WIP flags.
            

          

          

            
SemVer & App Backup Versions

            

              Bumps version.json (Patch/Minor/Major/Launch 1.0.0), manages the background file watcher, and saves/restores baseline or incremental workspace backups with diff summaries (SUMMARY.md).
            

          

        

      


      

        

          6. Developer Architecture, Feature Internals & Change Management
          Developer Guide
        

        

          Technical reference explaining how each subsystem works internally and how updates flow through versioning, backups, changelog tracking, Git sync, and automated tests.
        

        

          

            
A. Server Lifecycle, Security & Cache-Busting

            

              • run_server.py runs a supervised Uvicorn process on 127.0.0.1:8765 (--reload-dir app).
              
• app/main.py composes app/templates/index.html + partials/*.html via jinja2.Environment, injects modtool-session-token and ?v=<asset_version> (derived from version.json + newest static mtime), and enforces SessionTokenMiddleware (X-ModTool-Session) on mutating API calls.
              
• SafeMimeStaticFiles enforces JS/CSS MIME types with no-cache; app/static/sw.js uses network-first caching for / and /static/* with /offline fallback.
            

          


          

            
B. Backend Layers & Atomic Persistence

            

              • Core (app/core/): Shared constants in constants.py (eliminating cross-router imports), path/cache state and crash-safe atomic_write_json() (fsync + os.replace) in config.py, DPAPI token encryption in security.py, and token-redacting JSONL logging in audit.py.
              
• Engines & Services (app/engines/, app/services/): EngineAdapter implementations (Unity, Unreal, Generic) and focused services (discovery.py, game_store.py, mod_builder.py, tool_installer.py, pc_specs.py).
              
• Routers (app/routers/*): Thin FastAPI route handlers delegating to engines/services.
            

          


          

            
C. Frontend ES Modules & Action Telemetry

            

              • Native ES modules in app/static/js/ (main.js, api.js, state.js, game_table.js, active_game.js, unreal_panel.js, mcp.js, analyzer.js, git_backup.js, app_mgmt.js).
              
• main.js merges module exports onto window for inline HTML attributes and coordinates initialization + 5s health polling.
              
• runTrackedAction() drives inline progress slots, live scan polling (/api/games/scan-progress), copyable error details, and automatic client error auditing (POST /api/audit/client-error).
            

          


          

            
D. Safety Nets: Per-Game Snapshots & Conflict Guard

            

              • app/services/game_snapshots.py writes lightweight SHA-256 manifests + payloads of modded surfaces to %LOCALAPPDATA%\TheModdingTool\game_snapshots\<slug>\<timestamp>\, validating every copy/delete against ensure_within() and strict segment rules.
              
• Auto-snapshots trigger before loader installs, mod deployments, BepInEx provisioning, and Unreal INI writes.
              
• app/services/conflict_guard.py detects Vortex/MO2 deployment markers, proxy DLLs, and ~mods overrides before installation, returning structured conflict_warning responses until explicitly confirmed with force: true.
            

          


          

            
E. Updates & Change Management Workflow (Versioning → Changelog → Backups → GitHub Sync → Tests/CI)

            

              1. Semantic Versioning & Changelog (version_manager.py, version.json, CHANGELOG.md): Versions follow 0.MINOR.PATCH (pre-launch) through 1.0.0. Bumps update version.json (and invalidate asset_version for browser cache-busting), while append_changelog_entry() prepends newest-first ## YYYY-MM-DD HH:MM — vX.Y.Z sections recording the Prompt, AG Feedback, and file/behavioral Version Changes.
              
2. Workspace Backups & Pre-Update Snapshots (backup_manager.py, app/routers/git_sync.py): backup_manager.py captures baseline and incremental workspace versions in ./backups/ (manifest.json + unified diffs in SUMMARY.md + restore.ps1, using ensure_within()). Before applying a GitHub pull (POST /api/app/sync) or snapshot rollback (POST /api/app/rollback), git_sync.py automatically creates a safety snapshot in %LOCALAPPDATA%\TheModdingTool\app_backups\ so broken updates can be reverted immediately.
              
3. GitHub Branch Pull & Safe Push (git_sync.py, git_backup.js): Tokens are encrypted via Windows DPAPI. Pulling updates fetches remote commit metadata, downloads and SHA-256-hashes the target archive, snapshots current files, extracts cleanly into app/, and bumps installed commit state. Publishing code pulls remote+local branches via POST /api/app/git-branches into the Push Branch dropdown, opens the confirmation warning modal showing the exact target branch, runs non-interactive git CLI steps with credential redaction, and logs failures as sanitized GIT_PUSH_FAILED audit records.
              
4. Verification, Packaging & CI (tests/, package_windows.py, .github/workflows/ci.yml): Domain test modules (test_discovery.py, test_unreal.py, test_mcp.py, test_system.py, test_security.py, test_frontend_contracts.py) verify API schemas, security redaction/traversal guards, PyInstaller bundle paths (templates, partials, engines, services), zero duplicate DOM IDs, and ES module export contracts. GitHub Actions runs python -m pytest tests/ -v automatically on every push/PR to main.
